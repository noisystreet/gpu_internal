================
阅读路线建议
================

.. epigraph::

   Some books are to be tasted, others to be swallowed, and some few to be chewed and digested.

   — Francis Bacon

本教程按**从底层到上层**的次序组织，各章节之间存在依赖关系。根据读者的知识背景和阅读目的，推荐不同的阅读路线。

章节依赖关系
====================

.. code-block:: text

   绪论 ← 了解背景和范围
     │
   硬件结构 ← 基础（建议所有读者阅读）
     │
     v
   执行模型 ← 依赖硬件结构
     │
     ├──→ 驱动 ← 依赖执行模型（偏系统软件层面）
     │
     └──→ 运行时 ← 依赖执行模型（偏应用编程层面）
              │
              ├──→ GPU 互联拓扑 ← 依赖运行时
              │
              └──→ GPU 虚拟化 ← 依赖驱动和运行时

阅读路线推荐
====================

路线一：完整阅读（推荐）
"""""""""""""""""""""""""

适合希望系统掌握 GPU 原理的读者，按章节顺序阅读：

::

   绪论 → 硬件结构 → 执行模型 → 驱动 → 运行时 → 互联拓扑 → 虚拟化 → 附录

路线二：应用开发者
"""""""""""""""""""

适合主要使用 CUDA/HIP 进行 GPU 编程的读者：

::

   硬件结构(内存层次) → 执行模型(全部) → 运行时(全部) → 互联拓扑 → 附录(术语表)

   驱动章节可按需阅读，了解通信机制有助于理解性能调优。

路线三：系统软件开发者
"""""""""""""""""""""""

适合从事 GPU 驱动、虚拟化或底层运行时开发的读者：

::

   硬件结构(全部) → 执行模型(Warp调度) → 驱动(全部) → 虚拟化(全部) → 互联拓扑

路线四：AI 框架/推理引擎开发者
"""""""""""""""""""""""""""""""""""""

适合从事 AI 框架或推理引擎开发的读者：

::

   硬件结构(计算单元/内存层次) → 执行模型(内存访问) → 运行时(CUDA Graph) → 互联拓扑

   附录(术语表)可作为日常参考。

本教程中的约定
====================

- **代码示例**：以 CUDA 为主，必要时提供对应的 HIP 版本
- **架构参照**：除非特别说明，NVIDIA 部分以 Ampere 和 Hopper 架构为参照，AMD 部分以 CDNA 3 为参照
- **专业术语**：首次出现时标注英文全称，如流多处理器（Streaming Multiprocessor, SM）
- **交叉引用**：使用 ``:doc:`` 指向具体章节，方便读者跳转
